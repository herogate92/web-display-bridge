## 실제 장비 검증 현황

이 개발 과정에서 가상 디스플레이 설치, 실제 확장 화면 활성화와 모바일 브라우저 연결까지 사용자 환경에서 진행했습니다. 다음 성능·복구 기준은 아직 통제된 조건에서 완료하지 않았으므로 보장하지 않습니다.

- iPad 9에서 1440×1080·60fps로 10분간 평균 수신 55fps 이상
- 원본 화면과 수신 화면을 함께 촬영한 지연 중앙값 150ms 이하
- iPad, iPhone, Android 기기 2~4대의 동시 독립 연결
- 1시간 연속 사용과 발열 측정
- Wi-Fi 단절, 모바일 잠금, PC 절전 후 재연결
- 강제 종료 후 모든 물리·가상 디스플레이 배치 복구
- 2160×1620·60fps 고화질 모드의 안정성

## 실기 인수 절차

1. Windows와 GPU 드라이버 버전, Virtual Display Driver 버전, 모바일 기기·OS·브라우저, Wi-Fi 조건을 기록합니다.
2. Windows 디스플레이 설정에서 각 가상 화면이 별도 확장 디스플레이로 보이고 서로 다른 창을 표시하는지 확인합니다.
3. 각 가상 화면에서 1440×1080·60fps를 선택하고 서로 다른 모바일 기기를 연결합니다.
4. `/test-pattern`의 움직이는 화면을 10분 전송해 각 수신기의 실제 fps, 손실률과 전송량을 기록합니다.
5. 같은 시간 표시가 보이는 원본과 수신 화면을 함께 촬영해 화면 지연을 계산합니다. 네트워크 RTT를 화면 지연으로 대신하지 않습니다.
6. 전체 연결 종료, 앱 강제 종료, Wi-Fi 단절, 모바일 잠금과 PC 절전을 각각 시험한 뒤 화면과 연결이 복구되는지 확인합니다.
7. 1시간 사용 후 PC와 모바일 기기의 발열, 프레임 저하와 연결 끊김을 기록합니다.

측정 로그는 `node scripts/report.mjs <session.jsonl> [report.json]`으로 요약할 수 있습니다. 로그에는 로컬 IP와 장치 정보가 들어갈 수 있으므로 공개 전에 개인 정보를 지워야 합니다.
